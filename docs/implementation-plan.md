# v2.4.2 实现范围

v2.4 增强作品规则的执行与审阅：统一规则正文入口、可选索引、输入固定、方案落点和逐项覆盖相互连接。公共能力与私有工作区继续独立，统一工作区支持多部小说和公众号单篇。规则检查不替代文学阅读与作者接受，实际交付以发行记录和验收报告为准。

| 方案落点 | 实现 |
|---|---|
| 独立私人工作区 | 明确 --workspace；多部小说和公众号单篇通过 catalog 定位，按访问范围划分仓库 |
| 规则正文与索引 | rules_file 为正文入口；可选 rules_manifest 固定来源、位置、适用范围与检查要求 |
| 写前与写后 | 读取适用规则、方案记录落点、审阅给出规则 ID 与产物证据 |
| 任务与稿件 | task_result、manuscript_result、内容 accepted 分别表达，不把保存候选当作合格 |
| 规则兼容 | 新 run 固定 rule_context，直接登记保存轻量审阅；旧无索引作品和历史快照继续恢复 |
| 旧行为兼容 | 单机本地用法、现有内容工具与相对默认值保留 |
| 候选提交 | git_collaboration.py package，绑定共同提交、内容登记与选用版本 |
| 贡献边界 | guard 检查只新增完整候选包，拒绝夹带正式文件修改 |
| 基准审查 | verify 核对包、当前登记与方案/正文；漂移时重新审阅 |
| 正式整合 | 主编顺序使用既有 add-revision / run register；实际作者决定保持独立 |
| 正文统计 | manuscript_check 显式正文／排除范围，保留叙事引用；legacy 默认兼容旧数值 |
| 审阅口径 | 审稿 1.0.2 区分当场叙述、铺垫、后果、回望，比例有单位、范围和分类依据 |
| 合写角色 | 章节与合作模板按需区分经历主体、素材作者、执笔者与确认权限 |
| 登记后恢复 | 核对旧条目和正文不变、新增登记及其来源，保留并解释实际 drift |
| 个人过程 | 独立本地副本保存个人 run/lifecycle，不合并到正式链 |
| 迁移 | 来源读取核对、共享范围清单、全量备份、私有远端和克隆验证 |
| 可选外部工具 | Git/GitHub CLI 足以协作；腾讯文档保留导入/导出和历史读取 |
| 验收 | acceptance-v2.4.2.json：独立 D01–D06；实际执行、私人证据与历史回归分别报告 |
| 发布 | 公共能力完整 ZIP、独立 1.0.0 作者包，不含真实作品 |

13 项原子能力、素材映射、输入快照和恢复规则继续有效。方法卡、作者包及作品方案没有内容变化时不随产品升级升版。候选包是审阅单位，PR 合并不是作者接受正文。

不新增常驻同步服务、多人自动正文合并、分布式锁、应用层加密或全局目录定位配置。本地 guard 是审阅辅助，不能代替仓库成员与分支权限。迁移只核验完整性及恢复，不重写真实章节。
