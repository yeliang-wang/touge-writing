# v2.4 架构与边界

本项目是宿主执行的写作能力包和本地文件工具。公共项目可从 GitHub 更新，私人作品位于明确选择的目录，推荐为 `~/.touge-writing/workspace/`。没有常驻服务、数据库、向量库、自建 MCP 运行时或自动发布器。

公共项目名称为 `touge-writing`；统一私有工作区可命名为 `touge-writing-workspace`。两者是能力与创作资料的边界，不是一对一的作品关系。一个 workspace 的 catalog 同时管理多部小说与公众号单篇，作品事实和生命周期按作品 ID 隔离；Git 访问权限仍以仓库为边界。

| 部分 | 职责 | 状态归属 |
|---|---|---|
| Codex | 理解用户任务、写作、审读、执行工具、管理授权与连接 | 宿主会话及实际授权记录 |
| 两项 Skill | 选择方法、恢复作品、遵守任务阶段、显式选择 workspace | 不复制作品事实 |
| 原子能力 | reader-contract 至 editorial-review 的独立子任务方法 | registry 中显式 ID 与版本 |
| 作者表达包 | 判断方式、语言、词汇与审稿参考 | 独立 manifest 和版本 |
| 生命周期定义 | 全书、章节、文章的可进入阶段与完成条件 | 公共定义，具体运行私有 |
| 作品规则 | Markdown 正文、可选索引、来源、适用范围和审阅覆盖 | 作品私有；公共工具校验绑定，不决定文学质量 |
| 私人 workspace | 作品、素材、人物、方案、稿件与决定 | 本地目录或独立私有 Git 仓库，按访问范围隔离 |
| 候选包 | 选定产物、审稿、共同提交和内容指纹 | contributions；主编核对后顺序整合 |
| Python 工具 | 检索、映射、哈希、版本、锁与恢复 | 文件，单机协作锁 |
| MCP | 读取外部资料与按授权交付 | 宿主凭据、私有远端回执 |

方法选择顺序：当前明确请求与有效授权 → 作品已确认约定 → 约定内的章级细化 → 能力建议。新的明确变更记录范围并新建版本，不修改旧决定。事实冲突不由优先级自动裁定。

`rules_file` 是作品规则正文入口，`rules_manifest` 是可选索引。解析器按目标和任务类型确定本轮规则，run 固定其引用文件；宿主读取正文、在方案安排落点并审阅实际稿件。规则依赖完整、覆盖字段齐全和文学判断可信是不同结论。审阅任务完成可以伴随稿件 `needs_revision`，最终接受仍归内容登记及作者决定。[规则执行](rules.md)

## 工作区位置与更新

新版 Skill 和文档显式使用 `--workspace`；旧 CLI 不传参数仍使用当前终端目录下的 workspace。没有全局配置、环境变量优先级、自动跨目录搜索或跨作品索引合并。路径选择完成后，本次任务的内容、run、素材和外部记录使用同一个工作区。

init 创建必要索引和作品文件；resume 显示实际工作区与作品位置。已有作品先迁移或显式沿用旧目录，不能用新空索引掩盖原资料。更新公共项目不改变私人文件。[迁移](migration-v2.2.md)

## 四种数据职责

`版本记录/revisions.json` 是内容存在、继承和 accepted 的唯一依据。`lifecycle/events/` 记录任务阶段及操作；`runs/` 固定输入、方法快照和候选；两个 state.json 是可重建视图。试写可以不登记为当前正文，run completed 不等于 text accepted。

来源版本 → 事件／主题 → 章节或文章用途 → 正文版本为多对多关系。章 ID 独立于显示序号和标题；映射不自动改变旧稿和章序。来源身份、已读范围、事实确信度和虚构许可独立表达。

## 合作与外部服务

公开能力仓库与私人作品仓库是两个独立 Git 根，不需要 submodule。私有仓库以共同提交提供内容基准，实际成员权限决定可见范围。每个贡献者从同一提交在独立本地过程副本写作，只将选定产物提交为候选包；个人内容登记及事件链不按行合并。[合作](collaboration.md)

package 锁定 Git 提交、作品登记、相关方案与正文哈希；guard 审查变更范围；verify 校验当前基准与包。它们不提供身份签名、服务端访问控制或自动整合。主编在当前正式版本上顺序执行既有内容登记，实际作者决定仍是 accepted 的前提。

Git 操作可由本地 Git/GitHub CLI 完成，无需 GitHub MCP。腾讯文档可以用于导入、审稿、导出和历史参考；选择 Git 为正式存储后不建立第二个自动定稿入口。外部写前核对基准，写后回读，结果不明先对账。MCP 只连接外部服务，既不拥有作者决定，也不改变内容登记职责。

## 文件模型及限制

沿用不可覆盖版本、文件锁、哈希、操作 ID 恢复和输入快照。每次操作文件原子落盘，但不承诺跨文件事务；中断靠原输入和内容指纹对账。模型输出不因输入哈希相同就逐字可重现。

工作区是普通 Markdown、JSON 等文件，备份无应用层加密。Git 私有权限不等于只有作者持钥的端到端加密。加密需求由系统磁盘或加密卷承载；只共享授权内容，并同样保护备份。方法不能弥补所有材料缺口，统计器也不裁定文学质量。程序检查、文本审读、协作演练和作者审美判断在验收中分别报告。[runs](runs.md) · [素材](materials.md) · [测试](testing.md)
