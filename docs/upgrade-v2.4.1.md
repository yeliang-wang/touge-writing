# v2.4.1：扩写、节奏和初稿确认

本次升级将实际写作中反复出现的操作问题整理进已有方法：材料增加了，正文怎样变丰满；长段怎样拆得自然；重复回望怎样压缩；作者确认初稿后怎样保留正确状态。没有新增运行框架、管理命令或数据格式。

## 公共能力的改动

| 问题 | 本版处理 |
|---|---|
| 扩写容易离开原有主体，或用同一结论反复填充 | 场景设计先记录保留事件链与可用材料，新增文字须带来行动、限制、选择或后果；不足处保留缺口 |
| 按固定段数、等长段落组织，读起来机械 | 分段随动作、说话者、情绪和认识转折；通读检查承接，避免改成每句单段 |
| 回望和结尾重复同一个道理 | 逐次检查认识增量，合并重复；收获由事件推导，具体格式遵循作品约定 |
| 统计结果被误当作质量证明 | 字数、段长和比例只作口径明确的描述，语义审阅另给位置、理由、收益与代价 |
| 确认初稿被误记成终稿，或再次登记相同正文 | 绑定既有 revision ID、哈希与实际决定，保留 draft；不改写旧审阅的历史状态 |
| 清单把骨架、历史稿和试写计为当前正文 | 依据登记的当前版本和作者记录汇总，非正文和未登记附录单列 |

`scene-design`、`reflection-shaping`、`editorial-review` 增加 1.0.1，旧 1.0.0 保留。仍有 13 项独立能力，16 条版本记录。新任务使用更新后的组合；已经保存的 run 继续按原快照与版本执行。

两项 Skill 同步这些执行边界。公众号仍是单篇写作，不因复用场景方法变成长篇小说流程；同一 workspace 可通过 catalog 管理多个独立作品目录。

## 私人作品怎样跟进

公共升级不自动重写正文、修改作品计划或接着写下一章。已有作品只在确有新作者决定需要纳入后续任务时，新建其私有规则整理版本，并保留旧规则、来源、审阅与快照。

人物、真实经历、素材、特定篇幅、段数与结尾点数属于各自作品。局部决定只在授权范围生效，不能借公共升级取消全书旧要求。有冲突时保留来源并说明适用范围。workspace schema 仍为 1；工作区无需跟随公共产品创建文学版本号。

作者表达包保持 1.0.0。本轮沉淀的是执行和审阅方法，不是新增作者习惯用词或改写公共人格。

## 验证边界

按 [测试与验收](testing.md) 执行 D01–D06。补丁配置、独立合成案例和报告使用 v2.4.1 路径；缺少当前证据时失败，不复用 v2.4.0 结果冒充本次验证。历史方法精确解析、多版本计数和证据隔离有程序回归；小说、公众号与初稿确认由独立 Agent 实际执行合成请求并保存产物。

完整发布还须核对私有历史保护、离线规则恢复、真实远端克隆和发行资产。六项通过才声明完成；机械检查不证明文学质量或真实作者审美认可。外部 MCP 协议未改，微信公众号真实账号操作仍不在验收范围，腾讯文档沿用明确标注的历史证据。
