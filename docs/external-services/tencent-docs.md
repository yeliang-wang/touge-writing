# 腾讯文档连接与操作 · v2.3.1

腾讯文档是可选的资料导入、外部审阅、导出阅读和历史参考渠道。使用独立私有 Git workspace 时，不要求腾讯文档作为终稿存储。本页面向仍需该服务的使用者。官方 MCP 地址为 [docs.qq.com/openapi/mcp](https://docs.qq.com/openapi/mcp)，个人授权入口为[腾讯文档授权页](https://docs.qq.com/open/auth/mcp.html)。每次新安装使用自己的宿主授权。

## 配置

在项目根目录的本机终端运行：

```bash
python3 scripts/configure_tencent_docs.py
```

脚本隐藏读取授权值，在 `~/.codex/config.toml` 添加 tencent-docs 服务，使用 Authorization 请求头。原配置备份仍在宿主目录，权限设为仅当前用户读取；已有同名配置时脚本退出，需检查现有项。按授权页提供的值填写，不自行添加 Bearer，也不在聊天或项目文件中传递它。

写入配置不等于运行中的宿主已加载连接。由宿主重新连接后检查工具列表、账号和目标权限；脚本自身不进行联网验收。

## 证据范围与版本沿用

v2.3 沿用 configure_tencent_docs.py 和 external_operations.py 的既有连接与写回协议；未变更范围核对历史真实回执、源内容与读回指纹。这是历史证据回归，不是本轮重新实测写入。迁移已有云端作品时另行执行当前读取与本地版本核对，该证据只覆盖实际读取对象。新账号、凭据、工具 schema 或调用协议改变时，使用独立测试对象验证受影响操作。

### v2.0 已验证操作

v2.0 私人验收已使用新授权验证：既有 Word 与目录表读取、空间目录遍历、`doc.create_with_markdown`、写入前 `doc.resolve_document_structure`、带基准版本的 `doc.find_and_replace`、完整 `get_content` 回读，以及本地操作记录。试验仅写入专用测试文档。

这些结果不是所有接口的保证，尤其不能推导为表格覆盖写入、图片排版、附件或任意文档类型均已验收。新账号和后续版本以当前 tools/list 与实际返回为准。

## 读取与更新

空间目录使用 `query_space_node`，检查 has_next 并继续分页；普通 `manage.folder_list` 返回空列表不能证明空间内没有作品。保留真实文档 ID、类型和链接，不根据标题猜测目标。

`get_content` 用于正文阅读；需要位置索引的修改先读取结构。检查工具返回的有效模式、分页和版本，不假设与请求模式完全一致。保存写入前快照，使用支持的版本条件，写入后检查完整正文、首尾和顺序。

云端人工修改先形成差异，再按具体任务处理回流。旧链接不可因类型限制而自动替换；不要把“清空后追加”作为通用更新算法。失败或超时先查询，避免重复追加。

回执使用[外部记录工具](../cli.md)留在本地。账号被识别、工具可见、HTTP 成功与正文正确是不同证据，应逐层核对。

## 可选云端协作与迁出

继续云端审阅时，各人使用自己的宿主授权，使用 [合作约定](../../templates/collaboration.md) 选定共享材料、用途和汇总负责人。本地调用 external_operations.py 时显式传入本人的 --workspace；记录只在本地，不能锁住远端。

负责人读基准后汇总写回，其他人提供候选和差异。远端基准变化时先停止覆盖并处理差异；新内容须有明确的共同确认依据才能导入为 accepted。历史单次操作回执与本版合成演练不能证明真实多人并发写入或自动合并已验收。[完整合作流程](../collaboration.md)

迁入私有 Git 前读取实际远端目录和全部已选正文，核对本地登记并保存差异。切换后在私人作品约定中标明正式仓库，保留旧文档作历史参考或按具体授权处理；迁移不自动删除云端原件。[迁移指南](../migration-v2.3.md)
