# v2.3 扩展外部 MCP 服务

面向宿主集成者。新增服务沿用 MCP 工具连接，不增加项目内的 Agent 或插件运行框架。

## 接入步骤

1. 根据实际任务选择服务，在宿主配置连接与认证。
2. 获取当前 tools/list，核对需要的操作、对象类型、权限、分页、错误和结果查询方式。
3. 在服务文档说明账号选择、目标定位、版本条件、内容完整性和已知限制。
4. 将入口链接到相关 Skill；必要时在 `external-services.example.yaml` 增加能力说明。
5. 在授权范围内用独立测试对象实测，并保存真实回执。服务注册或配置存在不等于 live verified。

示例配置是说明数据，不是可直接载入的宿主配置。服务名称不决定工具名；以当前服务返回的 schema 为准。

## 写入约定

选定本地作品版本、账号和远端目标 → 预读并核对远端变化 → 记录操作意图 → 宿主执行工具 → 回读或查询结果 → 保存实际证据。

更新应使用服务支持的版本条件；服务不支持时先比较预读指纹，并认识到检查与写入之间仍存在并发窗口。远端内容变化时记录 conflict，不静默覆盖。

结果不明先查询。记录器不会在远端实现幂等，重复提交前必须对账。凭据只在宿主管理；作品内保存账号别名、对象 ID、内容指纹和必要回执。

## 状态表达

区分 documented、configured、authenticated、live_verified 与 blocked。它们是服务说明中的状态标签；本地操作记录另有 prepared/submitted/verified/failed/unknown/conflict 状态。不能用一个代替另一个。

## 与运行记录结合

把要交付的内容登记 ID 作为 prepare 输入，run 可保存交付说明并引用外部 operation_id。外部工具失败不丢失本地正文，也不重跑全部写作阶段。新增服务一般只补服务文档和宿主连接，不改能力卡、内容登记或生命周期引擎；若变更公共写入协议则增加受影响操作的真实测试。
