# 测试与验收 · v2.4.1

程序完整性检查、写作方法评审、协作行为和作者审美认可分别报告。脚本成功不等于文学质量认可，合成材料也不替作者接受自己的书稿。

## 普通安装自检

```bash
python3 -m unittest discover -s tests -v
python3 scripts/preflight_check.py
python3 scripts/acceptance.py --public-only
```

公共模式不读取维护者私人档案、不连接账号。它验证既有工具、公共发行边界、外部临时 workspace、旧默认兼容、方法与作者包，以及私有 Git 合作工具的合成行为。新写作测试不向使用者真实 HOME 保存作品。

官方完整 ZIP 用 release-manifest 校验；GitHub 自动 source archive 没有该生成清单，建议在 Git checkout 自检。能力发行初始不含真实 workspace；使用者显式选择另一个目录创建或恢复作品。

## 维护者完整验收

```bash
python3 scripts/acceptance.py --workspace "$HOME/.touge-writing/workspace"
```

实际选定其他私有目录时替换参数。v2.4.1 使用 [acceptance-v2.4.1.json](../configs/acceptance-v2.4.1.json) 独立定义 D01–D06，与 v2.3 的 C01–C10 分开。公共模式运行 D01、D02、D03、D05，报告保存到 `work/acceptance-public-v2.4.1`；完整模式增加私有 D04、D06，写到所选 workspace 的 `acceptance-v2.4.1`。以执行报告中的 scope、结果及证据为准。

| ID | 验收目标 |
|---|---|
| D01 | 单元测试、公共边界、当前文档与 Skills |
| D02 | 干净安装、旧行为兼容和作者表达包 |
| D03 | 合成规则流程、Git 合作本轮执行及历史证据完整性 |
| D04 | 私人规则依赖、离线复制可用性及原历史保护 |
| D05 | 独立 Skill 行为演练 |
| D06 | 发行物与私有远端克隆证据 |

规则测试覆盖缺失依赖和漂移、目标与 mode 过滤、规则索引及正文绑定、审阅遗漏和过期产物证据、只审阅任务完成但稿件仍需修改、直接登记和 run 登记、未配置索引的作品以及旧快照恢复。机械通过只证明程序约束被满足；文学效果须单独审阅实际文字。

历史 v2.0 至 v2.3.1 验收、评测和回执保留，不改名为 v2.4 结果。新验证分别写明本轮真实执行、合成行为演练、冻结历史完整性和未测试范围。升级没有改变外部协议时核验既有腾讯文档证据，不称为本轮重新调用；新账号或受影响协议变更另做对应实测。

## Git 合作与写作证据

合成合作应在独立 Git 根中建立共同基准和两个克隆，实际调用 package、guard、verify。覆盖完整候选提交、损坏包拒绝、正式资料夹带拒绝、登记和方案漂移拒绝、个人运行链不进入正式提交，以及作者明确决定后才登记 accepted。包清单校验不是身份签名，guard 也不是服务端权限系统。

合成案例应保存实际输入、工具结果及主编处理；仅匹配文档关键词不能代替行为。真实私有远端的 owner-only 配置与干净克隆可证明该次迁移范围，不证明另一个真实协作者已经接受邀请或完成多账号并发测试。

v2.1 六组冻结写作案例、v2.2 合作案例保留历史身份与产物。沿用时标注为历史回归，不写成 v2.4 新写作或盲测。真实作品只核验资料、索引、继承和状态恢复，不在产品发布期间重审或改写章节。

## 外部服务、备份和限制

迁入 Git 前重新读取现存云端正文，核对当地实际状态；这与旧 Tencent MCP 写入协议的历史回归是不同证据。连接、目标定位、写入或回读协议改变时需要受影响操作的真实检查。只读取迁移来源不证明所有写入接口已重新验收。

微信公众号沿用明确范围：建立能力和说明，不做账号连接、读写或发文验收。腾讯文档在使用上为可选连接，迁移某本实际使用云端的作品时仍须核对其来源。

私有 Git 保存选定共同内容，完整个人备份覆盖未入库资料；两者分别核验。GitHub Private 和未公开上传不等于应用层加密。本项目不提供自动正文合并、分布式锁或端到端加密。

“100%”只指明确且实际执行的验收项全部通过，不代签作者审美认可，也不将未测试能力写成已验证。

D06会实际读取GitHub仓库身份与可见性、默认分支提交、发行标签及资产列表，并重新下载ZIP校验版本、成员和SHA。仅填写本地publication回执、拥有本地clone或复制一个同名文件不能证明已发布。完整验收需要可用的GitHub CLI与网络；失败不降级为已验证。

补丁版本严格匹配自己的配置与证据目录，不回退使用早期版本的合成结果。v2.4.1 的 D05 在 [独立行为评估](../evals/v2.4.1/rules-behavior/README.md) 中保存小说扩写、公众号节奏修改和初稿确认三组实际输入与产物，并绑定当前 Skill、配方及三张 1.0.1 方法卡。三项新增方法版本不增加能力种类，旧 1.0.0 仍可精确解析。v2.4.0 的配置、合成产物和报告继续保留。
