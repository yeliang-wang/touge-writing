# 测试与验收 · v2.2

确定性程序检查、真实文本的方法评审、合作流程演练和作者审美认可分别报告。脚本成功不等于文学质量认可，合成材料也不替作者验收自己的书稿。

## 普通安装自检

```bash
python3 -m unittest discover -s tests -v
python3 scripts/preflight_check.py
python3 scripts/acceptance.py --public-only
```

公共模式检查既有接口和新增边界、公共发布范围、独立临时工作区安装、旧默认兼容、13 张能力卡、作者包、合成协作及 v2.1 冻结文本证据回归。它不读取维护者私人档案或连接账号，也不声称完成私人迁移和真实外部验收。

官方完整 ZIP 用 release-manifest 校验；GitHub 自动 source archive 未带该清单，建议在 Git checkout 自检。干净安装需证明：发行包初始没有私人 workspace；显式外部目录可新建、恢复公众号与小说；旧命令仍在测试临时目录创建原相对工作区。不能向使用者的真实 HOME 写测试作品。

## 维护者完整验收

```bash
python3 scripts/acceptance.py --workspace "$HOME/.touge-writing/workspace"
```

v2.2 报告写到所选 workspace 的 acceptance-v2.2，历史 acceptance 和 acceptance-v2.1 保留。验收定义见 [acceptance-v2.2.json](../configs/acceptance-v2.2.json)。本版 B01–B10 单独统计，公共模式检查 B01–B07，私人 B08–B10 需要实际迁移与历史外部证据；公共通过不等于完整发布验收。

## 合作与写作证据

合作演练使用合成资料，覆盖只分享选定文件、两人本地过程隔离、共同基准、待审稿与 accepted 的区分，以及远端基准变化时暂停覆盖。需要 实际宿主按照 Skill 和协作说明处理任务，不能只用文字包含关键词代替行为演练。共同确认必须有案例中明确给定的合成决定，不能从文档最新时间推断。

v2.1 的六组冻结案例继续作为既有方法回归：公众号直接成稿／改写、真实经历式冲突／材料不足、纯虚构连载／改写。保留足量正文、审稿、失败及修订，以及生成者自评与复读的区别。沿用这些产物应明确是历史证据回归，不写成 v2.2 新生成或盲测。公开方法示例可见的有界验收不代表泛化基准或 WorkBuddy 性能比较。

迁移真实作品时，只验证资料完整性、索引、版本继承和已保存状态恢复。恢复章节审稿阶段不自动执行该审稿；产品发布不依赖重新判定真实书稿质量。

## 外部服务和存储范围

腾讯文档协议未变时核验既有真实读写回执、目标与内容指纹，并标注历史来源。若改连接、目标定位、写入或回读，追加受影响操作的真实检查。合成冲突演练与历史单次操作回执不能证明新账号或真实多人并发编辑已经验证。

微信公众号按用户明确范围，只建能力与说明，不做账号、读写或发文验收。工作区及备份无应用层加密，存储加密由系统或加密卷承担；验收不能将未上传 GitHub 写成已加密。

100% 只指明确范围的检查全部通过，不代签作者审美认可，也不消除服务并发窗口等已说明限制。
