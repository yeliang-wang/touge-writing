# 开发约定 · v2.4.2

先分清改动属于方法、状态工具、作者表达还是某部作品。公共源只接受去除作品事实的规则、合成测试和技术文档；真实反馈先保存在私人区。项目根 AGENTS.md 与两项 Skill 为路由入口。

## 改写作方法

新增能力版本目录并更新 registry 的路径、语义版本和 SHA-256，保留已发布版本。卡片必须写适用范围、输入输出、完成条件、失败处理、事实／虚构约束和合成例子。Skill 只编排与引用。作者包有自己的 manifest；没有改变表达规则不因产品升级升版。既有 run 快照不可覆盖。

方法变化用实际写作案例检查。评测任务及最低条件先冻结；保留失败稿和修订，不事后放宽标准。独立评审与生成者自评如实区分，公开例子可见的验收不称盲测。

## 改确定性工具

复用 workspace_lib 的路径范围、不可覆盖复制、单机锁和原子写入。内容登记 schema 1 与 v2.0 兼容，未知未来 schema 拒绝写入。任一新状态先明确其唯一权威数据，state 文件只能派生。测试异常恢复：复制后未记事件、正文登记后未记事件、相同操作 ID 换输入、锁冲突、路径逃逸。

```bash
python3 -m unittest discover -s tests -v
python3 scripts/preflight_check.py
python3 scripts/acceptance.py --public-only
```

公共代码不依赖某本私有小说存在。辅助命令继续回归，公开上下文导出禁止混入 run/素材/凭据。涉及 MCP 连接或写回协议的变更须追加对应真实外部证据，单元测试不能替代。[验收](testing.md)

## 工作区与合作边界

新版路由显式传推荐外部 workspace 或用户指定位置，保留现有 CLI 的相对默认值；不加入全局配置、环境变量或自动切换另一份同名作品。测试只使用临时目录，尤其不能写真实 HOME 下的推荐位置。初始化遇到未登记旧作品应拒绝并提示核对，不能创建空索引将其隐藏。

Git 协作工具限制候选提交范围并核对基准；主编顺序登记，不为多分支事件链添加自动合并。合作约定和外部操作由宿主执行，不增加分布式锁或同步服务。包哈希不是身份签名，作者确认的真实性须由宿主核对。测试使用两个临时克隆、合成作品及实际工具操作；真实确认记录、账号和稿件不得作为公共 fixture。v2.3 的报告与旧证据分开保存；迁移不重写原正文、继承记录和历史回执。

v2.4 的规则测试应覆盖缺失／漂移依赖、目标与任务类型过滤、索引与正文绑定、覆盖遗漏和过期稿件证据、审阅任务完成与稿件结论分离、直接登记与 run 登记、无索引旧作品及历史快照。机械校验只判结构和绑定；另用合成任务评估 Skill 是否读取适用规则、保留候选和诚实报告缺口。不得用文档关键词匹配代替执行证据。[规则](rules.md) · [本版验收](testing.md)

本轮补丁的范围与兼容说明见 [v2.4.2 升级说明](upgrade-v2.4.2.md)。方法按 ID 与显式版本解析；能力数量按独立 ID 统计。验收按 VERSION 使用独立配置、行为证据及输出，保留既有版本记录。
