# v2.0 开发指南

面向修改代码、Skill 或技术文档的维护者。先读根 [AGENTS.md](../AGENTS.md)，保持公共能力、私人作品和宿主外部连接的职责边界。

## 定位修改

| 需求 | 入口 |
|---|---|
| 文章或小说工作流 | `.agents/skills/` 与对应参考资料 |
| 作者表达规则 | `shared/author-expression/`，记录来源与适用文体 |
| 文件、版本、状态与恢复 | `scripts/workspace_lib.py`、`writing_workspace.py`、`backup_workspace.py` |
| 平台操作记录 | `external_operations.py`；实际调用仍由宿主执行 |
| 能力声明与验证范围 | `configs/` |
| 文档与使用示例 | `docs/` 和各模块 README |

新增能力先说明行为与材料需求，再登记配置并添加合成评测。配置中的 mode 是语义入口；若需要 CLI 支持，必须核对相应 parser，而不是只增加一个字符串。

## 验证修改

```bash
python3 -m unittest discover -s tests -v
python3 scripts/preflight_check.py
```

对版本、路径、恢复或外部记录变更，测试可观察的不变量，避免只匹配实现文本。文档命令在临时工作区运行；外部写操作不能以单元测试名义触及真实作品。完整迁移发布检查由持有私人验收证据的维护者运行，见[测试说明](testing.md)。

## 文档约定

README 提供最短使用入口；docs 按安装、架构、数据、命令、迁移、测试、发布分工。模块 README 解释该目录的责任并链接技术参考。保留旧技术文档路径作为兼容入口，移除与 v2.0 冲突的旧版本结论。

技术行为以代码、配置和测试为准。明确已实现、可选依赖、示意契约和未来集成的区别。作者风格统计是历史来源证据，不因软件升级重写成新统计。

## 公共变更审阅

检查工作树与暂存区，确保私人目录、凭据、真实回执和全文语料没有被加入。只从审阅后的 Git 树构建发行物；不能压缩整个本地目录。详细流程见[发布说明](releasing.md)。

本地 `workspace/` 不进入公共贡献。不要修改原稿来让工具测试通过，也不要把迁移状态恢复解释成发起新的写作任务。
