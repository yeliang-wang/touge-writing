# 从本地或腾讯文档迁入独立私有 Git workspace · v2.3

本指南将已选作品的共同存储迁入独立私有仓库，保留现有内容版本和作者决定。公共能力项目继续独立更新；迁移不改写章节，不把草稿升级为终稿。已有本地用法可以继续使用，无需为了升级而启用 Git 协作。

## 迁移前清点

1. 明确原 workspace、作品稳定 ID、新仓库范围和今后的唯一工作目录。按作品或相同权限团队选择仓库；私有仓库成员可以看到全部已上传文件及历史。
2. 读取 catalog、内容登记、当前方案和实际文件，盘点源材料、素材清单、历史路径与跨目录引用。只选正文会遗漏继承和证据；整个个人 workspace 上传又可能暴露无关资料。
3. 若腾讯文档曾作为共同存储，重新读取目录和每份目标文档，保存内容、身份和读取证据。与本地稿件比较；差异作为独立快照待处理，不能用 mtime 或云端最新时间代替作者接受决定。
4. 明确纳入清单：作品方案、正文、已确认版本、必要素材、历史和实际决定。另列仅在本地保留的完整语料、大型归档、原始外部回执、个人运行过程和无关作品。

## 完整备份与定向迁入

使用 [备份命令](cli.md) 在原 workspace 之外生成完整备份，恢复到新目录并逐文件核验。完整备份保留未进入私有 Git 的材料，不因共享清单缩小而丢弃原档。

在公共能力仓库之外建立目标 workspace。复制选定文件，生成只包含获准作品的 catalog；保留稳定 ID、不可覆盖正文、版本登记、历史方案继承和决定内容。需要迁移来源索引时使用新的工作副本或映射，原始来源和历史回执保持原样。对无法解析的依赖明确记录其保留位置，不能把缺失内容标成已迁入。

在目标根编写 README、合作约定和 `.gitignore`。README 应说明配套能力版本、使用路径、现行稿与已确认稿的入口、共享范围、个人备份位置的查询方式及本地专用资料边界。实际账号、远端 ID 和路径只放私人文件，不回写公共能力项目。

目录规划可参见 [workspace](workspace.md)。忽略规则不能移除已跟踪文件或 Git 历史；首次提交前必须审阅整个候选文件清单及文件内容。运行链若获准保留为迁移历史，明确它的历史身份；协作者此后的个人链仍不能并入正式链。

## 建仓、推送与回读

在目标 workspace 自身初始化独立 Git 仓库，不将它作为公共项目的子目录或 submodule。可以使用 GitHub 网页或已经配置的 GitHub CLI 创建 **Private** 仓库；推送前核对目标所有者和仓库可见性，凭据继续保存在宿主认证机制中。

先提交经过核对的资料，再推送到私有远端。另建干净克隆，确认以下结果：

- 远端确实是 Private，实际协作者与获准名单一致；未要求邀请时不添加成员。
- Git 提交与共享清单一致，克隆文件哈希匹配，没有意外账号密钥或无关个人材料。
- `resume`、`validate` 能解析目标作品；内容 accepted 状态和方案继承保持原值。
- 已登记正文、实际决定和必要素材可读；遗漏依赖被修复或明确标注，不伪造完整性。
- 两个隔离克隆可完成候选包与主编顺序登记演练，旧基准候选受到拒绝。

演练使用合成材料，不替真实作品创建确认决定。真实迁移的正文与登记不因演练被改动。

## 切换与恢复

完成回读后才将新目录设置为日后写作入口，所有脚本显式使用它的 `--workspace`。历史腾讯文档可继续只读参考；需要更新、删除或撤回共享权限时按该具体动作的授权执行，不因迁移成功自动删除云端原件。

原 workspace 和完整备份保留到约定的保留期限。回退时先停止写入、核对迁移后新增内容，并恢复到独立目录；不能用旧备份覆盖新稿。Git 恢复已提交的共同内容，完整本地备份恢复未入库资料；两者的覆盖范围不同。

这是一项存储与协作迁移，成功条件是范围明确、资料完整、版本关系保留、私有远端与恢复可验证。它不自动通过章节方案 review、不接受新正文，也不公开发布作品。
