# 合作写作 · v2.2

面向共同创作或互相审稿的作者。每个人安装完整能力项目并维护自己的私人 workspace；通过腾讯文档交换明确允许共享的方案、待审稿和共同确认稿。本项目不共享整套 workspace，不自动双向同步，也不自动合并两个人同时写入的正文。

## 先约定共享范围和负责人

将 [合作约定模板](../templates/collaboration.md) 保存为本作品的私人文件，填写实际分工、共享文档、采用的方案版本、汇总负责人和确认权限。模板里的占位符不是实际授权，公共模板不保存真实账号、远端 ID 或作品内容。

| 合作方式 | 通常需要共享 |
|---|---|
| 校稿、提意见 | 待审正文、希望关注的问题和允许修改的范围 |
| 分章创作 | 共同采用的全书与相关章节方案、必要人物和时间线、分工及待审正文 |
| 汇总确认稿 | 精确正文版本、差异说明、确认人的实际决定及适用范围 |

私人经历原件、未采用草稿、无关作品和完整运行记录默认不共享。允许合作方阅读不等于允许发布，云端文档编辑权限也不等于作品的确认权限。双方可以在 workspace 中保留不同数量的材料。

## 一次合作的流程

1. **读取共同基准。** 通过各自宿主账号读取约定的腾讯文档，核对文档 ID、内容和可取得的版本。将获准使用的正文保存为本地新快照，记录来源、读取时间、版本或内容指纹。方案继承明确版本；显示章号不作为章身份。
2. **在本地写作。** 在各自 workspace 保存任务输入、候选稿和审稿。共同基准之外的私人素材仅按实际授权使用；run 输入固定本轮采用的方案和正文。
3. **提交待审稿。** 由合作约定指定的人提交选定内容，说明它基于哪一版、修改了什么。写前读取指定远端目标并核对基准，写后完整回读。待审提交不改变本地 accepted。
4. **负责人汇总。** 根据各方意见形成明确候选版本，由约定有权确认的人作出实际决定。记录确认对象、范围与依据；最新编辑时间不作为确认依据。
5. **接收共同确认稿。** 各自在本地保存该确切内容为新版本，保留来源快照和确认记录。小说 accepted 正文仍须对应本地登记的同章已接受章节方案；必要时先导入并核对获准共享的方案和继承关系。未取得有效确认时保留 draft 或可追溯 baseline，不伪造 accepted。

文档 ID、正文指纹、选用方案版本和实际决定引用应留在私人作品记录中。不同作者的本地 revision ID 可以不同；需要用远端身份及内容指纹确认所指的是同一份内容。

## 远端发生变化时

如果写入前发现腾讯文档已偏离本轮基准，暂停这次覆盖，保存差异并由负责人决定采用哪一版或如何整合。可以交付一个独立候选文件等待汇总，不用旧稿覆盖新稿。默认由指定负责人更新共同稿，两个 Agent 不同时覆盖同一目标。

使用服务支持的版本条件；若服务没有相应能力，预读和指纹比较仍存在检查后发生并发修改的时间窗口。单机文件锁只能保护本机，无法锁住另一人的 workspace 或云端文档。结果不明、失败或超时时先查询实际远端状态，再决定是否重试。

候选正文、远端同步状态、共同确认和本地内容登记分别保存。写回成功不代表作者确认，run completed 也不代表发布完成。

## 账号、存储与证据范围

每位合作者使用自己的宿主授权，不互传密钥。仅将双方允许放入腾讯文档的资料上传；如果内容禁止进入云端，就通过双方另行约定的安全渠道传递文件，本项目不自动增加同步渠道。

workspace 使用 Markdown、JSON 等普通文件；备份归档也没有应用层加密。需要加密时采用系统磁盘加密或加密卷，并保护备份。腾讯文档访问权限、账号授权和本地存储加密各自生效，不能相互替代。

v2.2 的合作演练使用合成材料验证工作约定、私人目录隔离、候选与确认的区分和冲突处理。腾讯文档协议未变时核验既有真实操作回执，并说明其历史范围；这些证据不能推导为新账号、真实双人并发写入或自动合并已经验证。详见 [腾讯文档](external-services/tencent-docs.md) 与 [验收](testing.md)。
