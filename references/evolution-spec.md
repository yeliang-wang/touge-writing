# v2.0 能力演进约定

按“私人材料 → 有来源的观察 → 具体作品反馈 → 可复用规则 → 合成评测”演进。来源材料留在本地，稳定规则才进入公共能力。

## 材料处理

`ingest_corpus.py` 可整理公众号、企微/飞书导出、产品文档、会议笔记、反馈与草稿，产生私人 manifest.jsonl 和 documents。脱敏只做有限模式替换，不保证彻底匿名化。

现有 `private_retriever.py` 消费另一种文章 JSON 数组清单。两者不能直接混用；适配时明确字段、正文路径、权限与来源映射。格式见[工作区数据](../docs/workspace.md)。

## 规则归属

作品事实、人物、日期和章节配额留在该作品。共享语言观察进入 author-expression 时记录证据、适用文体与作者决定，同时更新能力包独立版本和哈希。不要直接修改旧风格符号链接而忽略其共享目标和清单。

交流方法、产品判断和内容交付方法分别保留自己的场景边界。一次反馈不自动成为永久禁令；新产品事实必须由当前材料支持，不能从风格资料推导。

## 增加能力

在 capabilities.json 登记ID、描述、模式与引用，补充方法、模块说明和合成场景。模式声明不是可执行插件，CLI 支持需要相应代码。外部连接另按服务接入约定处理，不混入作者风格规则。

验证程序不变量和实际行为，再运行公共边界检查。v2.0 发布门槛由 acceptance.json 明确规定，不沿用旧文档中未实现或与当前范围冲突的数量门槛。作者偏好反馈属于后续使用质量改进，不能代替工程验收或伪造成已确认结果。
