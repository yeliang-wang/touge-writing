# 方法与作者表达的演进 · v2.3

作品反馈 → 私人候选经验 → 去作品事实的抽象 → 合成跨文体验证 → 明确 review → 公共能力新版本。个人经历与第三方原文不因提炼而公开。

## 素材与权限

ingest_corpus.py 产生 JSONL；旧文章抓取产生 JSON 数组。material_index.py 和 private_retriever.py 只读适配两者，分别处理 id、集合 source_id、正文路径、声明哈希与使用限制。检索范围显式指定，不自动跨作品；有限脱敏不保证匿名化。

## 分开升级

- 写作方法：capabilities/registry.json 登记显式版本；发布后不改旧卡片。Skill 的 recipes 选择组合而不复制正文。
- 作者表达：共享 judgment/language/lexicon 等规则变化必须有实际审阅依据，并更新独立版本和 manifest。产品升级本身不要求改作者包。
- 作品方案：事实、人物、时间、比例和审批约定留在 workspace；每次变化新建版本，历史继承不重写。独立私有 Git 只管理选定共同版本，不将作品事实升级为公共方法。
- 辅助能力：configs/capabilities.json 保留交流、产品问答等原场景；模式声明不等于已实现 API。
- 外部服务：工具及账号由宿主管理，能力说明不等于已认证／已实测；腾讯文档为可选渠道，Git 协作无需 GitHub MCP。

## 验证与反馈

先固定任务和最低交付条件，再生成实际文本和有位置证据的审稿。保留失败与有限修订，自评不能叫盲评，作者没有确认就不能记认可。程序检查与真实文字评价分开；private workspace 不用作公共测试夹具。[测试契约](../docs/testing.md)

存储与合作升级需要验证共享边界、基准变化、主编顺序登记、备份恢复及实际远端结果，不能由既有写作质量案例推导。保留 v2.1/v2.2 原始评测身份，迁移不改真实章节，也不替作者接受稿件。
