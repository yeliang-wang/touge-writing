# 运行维护手册 · v2.3

完整安装后显式传入私人目录；新作品用 init 建立，已有私有作品仓库直接通过 catalog 和 resume 恢复，再通过对应 Skill 执行任务。小任务可直接完成，需多轮恢复、输入锁定或素材冲突时使用 run。共享作者分数只作线索，不让小说套公众号评分阈值。

日常流程是恢复当前任务及有效内容 → 在明确范围找材料并阅读全文 → 按需选方法 → 交付实际正文／方案 → 审读修订 → 保存产物与真实决定。内容与方法都有版本，旧 run 使用快照；正文是否定稿仍看 revisions。

中断后用原 operation-id 和原输入重试。输入换了不能复用 ID；复制完成但未登记时先比哈希，正文登记而事件缺失时补引用。state 缓存可重建，不能手改缓存解决冲突。来源漂移须保留旧版本并更新采用关系，不能删历史掩盖问题。

定期在 workspace 外完整备份并恢复到新目录核验。私有 Git 仅保存选定共同内容，未入库语料、个人过程和大型归档仍需独立备份。远端操作 unknown 先查询回读，不能盲目重发。Git/GitHub CLI 足以完成版本协作，不要求 GitHub MCP；腾讯文档按任务用于可选导入、外部审阅、导出或历史读取，本地写作不依赖网络。

私人反馈形成候选方法，经抽象和合成验证后才进入公共版本；不直接改变作者包。发布需公共测试、私人回归、适用于改动范围的行为评测及发行校验。v2.1 的六组写作案例和 v2.2 的两组合作推演作为历史证据保留；v2.3 另外验证独立 Git 双克隆、候选包与基准漂移、主编登记，以及实际迁移的全量备份、云端来源核对和私有远端克隆。旧评测通过不替代本轮迁移结果。详见 [维护与开发](../docs/development.md)、[发布](../docs/releasing.md)。

公共能力与私人作品是两个独立仓库，工作区及备份放在安装目录外；升级公共代码不会搬移作品。私有仓库按作品或相同权限团队划分，首次入库核对获准文件和引用依赖。成员可读全部已上传内容与历史，仓库 Private 权限不提供只有作者持钥的端到端加密；本项目也没有应用层文件加密。

日常合作从明确共同提交开始。贡献者在独立本地过程副本运行写作，选定正文和审稿打包到干净贡献分支；guard 检查边界。主编先取得远端正式分支最新状态，再用 verify 核对包和本次确认的基准，之后顺序登记。工具不 fetch、不代替 Git 权限；个人 run/lifecycle 不能按行合并或重新编号后并入正式链。PR 合并不等于 accepted，实际作者确认仍须针对精确版本。详见 [迁移](../docs/migration-v2.3.md) 与 [合作](../docs/collaboration.md)。
