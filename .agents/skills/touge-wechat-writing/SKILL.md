# 公众号写作（短篇、单篇）· v2.4

项目根为本文件向上三级。读 [作者表达包](../../../shared/author-expression/PROFILE.md)。用户明确的工作区优先；否则推荐 `~/.touge-writing/workspace`。执行每个工作区命令都显式传入同一个 `--workspace`，一个工作区可包含多部小说与公众号单篇，通过该目录的 `catalog.json` 及稳定作品 ID 定位本次作品；CLI 省略参数仍保留旧的当前目录 `workspace` 行为。

首次使用外部位置前检查其索引及项目内旧 `workspace/catalog.json`。外部缺失而旧位置有作品时，先说明迁移路径并沿用已明确的选择，不创建空库掩盖旧作品；两处都有同名作品且去向未明确时先厘清，不能自动合并。已经确认的迁移目的地或本轮路径持续有效，不重复询问。脚本使用项目根下的实际路径，不能假设终端当前目录。新建与迁移见 [安装](../../../docs/installation.md)和 [工作区](../../../docs/workspace.md)。

## 从任务与材料开始

已有作品运行 `writing_workspace.py --workspace <本轮工作区> resume --project <ID>`，读实际正文和有效决定。本轮明确任务优先于旧的下一步建议。先明确读者、要表达的判断、范围与素材；用户要求直接成稿就交正文，不额外要求提纲审批。

读取作品 `rules_file` 与可选 `rules_manifest` 中适用于本篇和本轮阶段的规则正文，确认来源、继承及例外；不要只读规则 ID 或文件摘要。任务单说明规则如何落到文章，简单改动可用轻量核对。具体格式见 [规则执行](../../../docs/rules.md)，不强制为短文建立完整 run。

按 [组合指南](references/recipes.md)选择 [原子能力](../../../capabilities/README.md)，不每次全跑。需要旧文时用 `private_retriever.py --manifest <明确授权的清单> --query <事件或主题>`，继续阅读命中全文。JSON 与 JSONL 均支持；索引命中不代表已读或事实核实，空记录不当来源。来源与主题映射见 [素材说明](../../../docs/materials.md)。

不得为真实自述添加未提供的私人经历、动作、收入或他人心理。虚构例子须符合本次授权并能与真实材料区分。已有稿优先保留作者观点与有辨识度的句子，书稿改编需说明来源章节，不修改源书稿。

## 写作与审稿

根据任务交付标题、正文及必要摘要或说明。结构服务判断和阅读，不把每篇写成小说，不强迫处处冲突与升华。背景须帮助理解选择或代价，回望增加理解而非解释怎么编辑。作者声音来自判断、节奏和犹疑，词库不作口头禅配额。

审阅给出保留项、问题位置和修改理由，检查相邻论点是否换词重复。`manuscript_check.py` 只查可计算线索；实际文字审阅不能被“文件齐全”“零告警”替代。质量不足继续修具体问题；不能只创建记录就声称已成稿。

审阅逐项记录适用规则的正文证据、缺口或有来源的例外，不把快照存在视为理解和执行。仅审阅的任务可完成并结论为稿件 `needs_revision`，不自动转成改稿授权。保存候选只保留过程，稿件合格与作者接受另有依据。

## 保存与交付

按 [文章生命周期](references/lifecycle.md)从实际阶段进入。需要恢复多步修改时用 [run 记录](../../../docs/runs.md)固定输入、方法版本、候选和审稿；简短任务不强制记录全部步骤。正文和审稿分开保存。accepted 只由内容登记和实际作者决定建立；脚本不能代替作者审美认可。

Markdown 是创作源稿；HTML、排版和平台字段为可重建派生物。按需阅读 [公众号连接](../../../docs/external-services/wechat.md)或 [腾讯文档](../../../docs/external-services/tencent-docs.md)。Codex 管理 MCP，Skill 不启动服务。微信公众号沿用用户约定：建立能力与接入说明，真实账号和发文未实测、不纳入验收。

定稿、同步草稿、公开发布是不同操作。沿用已明确账号、版本和操作授权；外部结果不明先对账，不能因本地任务完成自动发布。

## 合作作品

有合作请求时读 [协作约定](../../../docs/collaboration.md)，采用作品已确认的私有仓库、共同提交、共享范围、主编和确认权限。公共能力仓库与私人作品仓库独立，不将作品加入公共发布。

贡献者从共同 Git 提交在独立本地过程副本运行写作任务；只把选定候选和审稿通过 `git_collaboration.py package` 放入干净贡献分支。提交前 guard，主编在最新正式版本 verify；基准或登记变化先保留差异并重新审阅，不强行覆盖。不要合并或重新编号个人 run/lifecycle 事件链，也不要把个人完整登记文件复制回正式仓库。

主编顺序使用既有内容工具登记新 draft；accepted 引用实际有权确认者对确切版本的决定，小说仍保持方案继承。Git 提交、PR 合并、run completed 和云端最新稿均不自动接受正文。包校验只证明完整性与基准，不证明文学质量或身份授权。腾讯文档可以作为选定资料的导入、审稿、导出或历史入口，按作品约定判断其职责；没有云端连接仍可完整进行本地和 Git 写作协作。
