# 小说写作（长篇、连载）· v2.4.1

项目根为本文件向上三级。读 [作者表达包](../../../shared/author-expression/PROFILE.md)。用户明确的工作区优先；否则推荐 `~/.touge-writing/workspace`。执行每个工作区命令都显式传入同一个 `--workspace`，一个工作区可包含多部小说与公众号单篇，通过该目录的 `catalog.json` 及稳定作品 ID 定位本次作品；CLI 省略参数仍保留旧的当前目录 `workspace` 行为。

首次使用外部位置前检查其索引及项目内旧 `workspace/catalog.json`。外部缺失而旧位置有作品时，先说明迁移路径并沿用已明确的选择，不创建空库掩盖旧作品；两处都有同名作品且去向未明确时先厘清，不能自动合并。已经确认的迁移目的地或本轮路径持续有效，不重复询问。脚本使用项目根下的实际路径，不能假设终端当前目录。新建与迁移见 [安装](../../../docs/installation.md)和 [工作区](../../../docs/workspace.md)。

## 恢复本次任务

运行 `python3 scripts/writing_workspace.py --workspace <本轮工作区> resume --project <作品ID>`，明确指定章节时加 `--chapter <稳定ID>`。同时恢复有效方案与历史继承、已接受和最新内容、本轮任务阶段、差异及未决项。active_task 优先于旧 next_action；恢复已保存审方案阶段本身不等于要求执行审稿。

按返回路径阅读全文：目标章、需要处理衔接的邻章、有效规则与人物设定。摘要须绑定实际文本哈希；excerpt 是节选，不代表已读全文。baseline 不表示符合现行方案。远章先查职责与已用主题，命中后再展开历史。不能用版本名、mtime 或旧表中的“第三章”确定身份和事实。

从作品 `rules_file` 与可选 `rules_manifest` 恢复统一规则入口，按目标章和任务阶段选适用项并读引用正文；规则 ID 和快照不是阅读证明。章方案写清继承版本、规则在本章的落点及有依据的例外，不能用局部细化静默取消全书规则。格式、阅读记录与覆盖检查见 [规则执行](../../../docs/rules.md)。

## 选材与写作

按 [组合指南](references/recipes.md)选择 [原子能力](../../../capabilities/README.md)，只读本轮需要的卡片。先判断材料是否足够：在用户允许的清单内按事件、人物、公司、时间、别名检索，继续读高相关原文及冲突上下文。读取与映射见 [素材说明](../../../docs/materials.md)。

真实材料只重述有依据的事实；真实经历小说按已授权范围重构场景、对白；纯虚构按设定创作。已有授权持续有效且可被本轮收窄。来源身份、事实判断与虚构许可分别记录，不把一章授权推广给另一章。年份、任职关系冲突只阻断依赖它的部分，其余任务继续。

场景任务必须交付可读正文，让行动、反应或状态变化可见；不把履历扩成更长履历。扩写已有章先明确必须保留的主线、因果与表达，再把新材料放入对应情节；每次增加篇幅应带来处境、选择或后果的增量。材料不足时定向补检索、提出关键缺口、压缩为过渡或交独立片段，正文外说明范围。

按动作、说话者及情绪转折分段，连续叙述可保留长段，停顿可用短段；连读衔接，不按等长或逐句拆分。回望只保留新增的理解，压缩与相邻段、章末收获重复的解释。读者收获从具体事件及其局限中提炼，形式与篇幅服从作品约定；公共方法不规定每章字数、固定点数或编号。背景只写与选择、限制和代价有关的部分。

## 方案、审阅与保存

[生命周期](references/lifecycle.md)区分全书规划和章级执行。章方案显式继承已接受的全书方案版本，不静默追随最新版本。遵守作品现有 review/draft 阶段；只审方案的任务不顺带写正文。新书初始化及章配置见 [工作区说明](../../../docs/workspace.md)。

审阅实际正文与必要邻文，给出保留项、位置证据和修订收益／损失；比较参考章时读取其确切版本全文。比较时间人物，也比较主题、意象、感悟、情绪落点和相邻段落是否顺畅。新增材料的效果与文字调整分别报告。保护作者真实犹疑和直率，不强制金句或口头禅。运行 `python3 scripts/manuscript_check.py <正文>` 只取得字面线索；字数与段长不证明节奏自然，也不构成文学或事实验收。

写后逐项核对适用规则，记录确切产物、位置、判断及缺口；不适用或例外须说明范围与来源，不能只填“已覆盖”。仅要求审阅时，可以完成审阅任务并报告稿件 `needs_revision`，不为完成任务擅自改写。写作任务仍有必需规则未解决时保留候选与问题，不能称其合格。小改用轻量核对即可。

需要多步恢复、素材冲突或试写留档时用 [run 记录](../../../docs/runs.md)锁定输入、方法与产物。小任务可直接交付，无需建所有目录。候选可只属于 run；采纳后 `writing_workspace.py add-revision` 或 `writing_run.py register` 创建新版本。accepted 必须引用实际作者决定；旧定稿、来源和历史方案不覆盖。完成试写不等于章节定稿。

作者只确认“初稿完成、待精修”时，把实际决定绑定既有 revision ID 与正文 SHA-256，保持 `draft`；正文未变就不重复登记，也不由版本名自动变成 `accepted`。后续精修另存新正文版本。更新章节清单时核对注册版本、实际作者决定与正文哈希，说明字数口径；骨架、未采纳片段和历史版本不重复计入当前正文，总纲与导航引用同一份当前清单。

需要外部资料或交付时才用 [腾讯文档](../../../docs/external-services/tencent-docs.md)等宿主 MCP。离线写作正常继续，操作回执私有保存；同步和公开发布分别按已有授权执行。

## 合作作品

有合作请求时读 [协作约定](../../../docs/collaboration.md)，采用作品已确认的私有仓库、共同提交、共享范围、主编和确认权限。公共能力仓库与私人作品仓库独立，不将作品加入公共发布。

贡献者从共同 Git 提交在独立本地过程副本运行写作任务；只把选定候选和审稿通过 `git_collaboration.py package` 放入干净贡献分支。提交前 guard，主编在最新正式版本 verify；基准或登记变化先保留差异并重新审阅，不强行覆盖。不要合并或重新编号个人 run/lifecycle 事件链，也不要把个人完整登记文件复制回正式仓库。

主编顺序使用既有内容工具登记新 draft；accepted 引用实际有权确认者对确切版本的决定，小说仍保持方案继承。Git 提交、PR 合并、run completed 和云端最新稿均不自动接受正文。包校验只证明完整性与基准，不证明文学质量或身份授权。腾讯文档可以作为选定资料的导入、审稿、导出或历史入口，按作品约定判断其职责；没有云端连接仍可完整进行本地和 Git 写作协作。
