# 作品合作约定

仅用于本作品；填写后保存在私人作品的决策记录中，按约定分享。本模板不是授权或定稿证据。

- 作品标识与共同方案：稳定作品/章 ID、全书和章节方案版本。
- 正式存储：私人仓库身份、正式分支、当前共同提交；如果沿用云端，填写具体文档及用途。明确哪个入口是共同来源。一个 workspace 可包含多部小说与公众号单篇；仓库成员会看到全部已提交作品及历史，只共享部分作品时使用独立仓库。
- 分享范围：允许入库的正文、方案、素材、历史及其使用限制；哪些资料只在个人本地备份。
- 分工：参与者、负责章节/任务、必要共同设定。
- 主编：唯一负责顺序整合和登记正式内容的人；替班时如何交接当前基准。
- 候选交付：各自从共同版本在独立本地副本写作，只将选定正文和审稿打包提交；PR 的审阅和冲突处理方式。
- 确认权限：谁有权接受正文/方案；需共同确认时列明全部必需确认者。PR 合并不自动视为正文接受。
- 确认记录：确切版本、确认人、实际决定来源、时间及适用范围。
- 外部阅读：腾讯文档等仅用于哪些选定导入、审稿或导出；回流修改如何审阅。
- 账号与退出：仓库成员维护人、邀请与撤权方式；已取得本地副本无法靠撤权自动删除。

开始前读取共同基准。候选包应绑定提交、作品登记和方案/正文哈希；基准改变先审查差异，不强制覆盖。个人 run 和 lifecycle 保留在本地过程副本，不合并或重新编号加入正式事件链。

主编在最新正式 workspace 中创建新版本，保存来源和实际决定；未确认时保留 draft。小说 accepted 正文继承已确认章方案，章方案继承明确全书方案。源文件、历史版本和历史决定不覆盖。Git 提交成功、PR 合并、run completed 与内容 accepted 分开记录。

私有仓库只提供访问控制，不提供只有作者持钥的端到端加密；本地文件及备份也须采用适合资料的存储保护。不得将宿主凭据放入任何作品仓库。

参见 [协作流程](../docs/collaboration.md)。
