# 私有 Git 作品库合作演练

本目录用于 v2.3 的独立前向验收。判据见 [protocol.json](protocol.json)。材料是新写的合成修钟小说，不包含任何作者的真实 workspace、语料或稿件。

演练创建一个临时本地 bare Git 仓库、主编与协作者的独立克隆，并从正式提交创建恢复克隆。协作者提交候选稿和审阅意见，主编验证提交包，依据明确标注为合成的作者决定登记版本。故障案例检查基准漂移、提交包篡改及正式状态的越权修改。

两个克隆运行在同一宿主。此记录不等于两个真实 GitHub 账号测试，不验证 GitHub 权限、在线 PR 规则、应用层加密或文学质量。正式库的 GitHub 访问控制仍应在实际仓库中配置。

只有实际执行产生且通过的结果，才能作为本轮验收证据；本说明和预设判据本身不是通过证明。

在公共项目根目录运行 `python3 evals/v2.3/git-collaboration/run_evaluation.py`。脚本使用临时目录，不访问个人作品库、不访问网络；默认更新本目录的合成演练证据，也可用 `--out` 写入另一个结果目录。

已执行结果见 [result.json](evidence/result.json)、[实际命令记录](evidence/transcript.json)、[恢复后的状态](evidence/accepted-state.json) 和 [正式文件哈希](evidence/official-inventory.json)。机器结果同时记录被测脚本与判据的哈希；相关文件变化后须重跑。

本轮 6 项通过，实际执行 60 条命令，其中 6 次预期拒绝：一次包正文篡改、一次旧登记基准、三个 Git 状态下的正式文件改动、一次有效包夹带正式修改。主编在审阅分支验证候选，验证通过后才并入主分支。正文采纳使用独立的合成决策记录与正式版本登记，贡献包合并本身不代表稿件采纳。

协作者本地确实运行了现有 `writing_run` 与 `add-revision`，并产生与主编不同但序号相同的事件。提交检查拒绝把这条分叉历史纳入正式库。该机制是提交和整合检查，不是禁止协作者修改自己本地文件的角色权限系统。
